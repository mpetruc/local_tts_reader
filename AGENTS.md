# Repository Guidelines

## Project Overview
The **Local TTS Reader** is a Chrome extension that reads webpage content using an OpenAI‑compatible text‑to‑speech (TTS) service. Users can trigger reading via a context‑menu entry or the popup UI, which streams audio generated by the configured TTS server.

## Architecture & Data Flow
- **manifest.json** defines the extension entry points, permissions, and host permissions.
- **Background service worker (background.js)**: creates an offscreen document for audio playback, handles context‑menu clicks, processes selected or whole‑page text, sends it to the TTS server, and forwards audio to the offscreen page.
- **Offscreen document (offscreen.html / offscreen.js)**: plays audio streams in the background.
- **Popup UI (popup.html, popup.js)**: provides controls (play/pause/stop/seek), loads saved settings, and communicates with the background via `chrome.runtime.sendMessage`.
- **AudioPlayer (audioPlayer.js)**: thin wrapper that forwards playback commands from the popup to the background.
- **TextProcessor (textProcessor.js)**: normalises markdown/HTML, sanitises URLs and symbols before sending text to the TTS service.
- **constants.js**: default configuration values (server URL, voice, speed, etc.).

Data flow: UI → background → offscreen → audio output. All communication uses Chrome extension messaging APIs.

## Key Directories / Files
- `manifest.json` – extension manifest (entry point, permissions).

## Code Conventions & Common Patterns
- **Plain JavaScript (ES2022)** with `async/await` for async operations.
- **Chrome Extension Messaging**: `chrome.runtime.sendMessage` / `chrome.runtime.onMessage.addListener` for UI‑background communication.
- **Offscreen Document**: used for continuous audio playback (`chrome.offscreen.createDocument`).
- **Constants module**: centralises default settings; imported where needed.
- **Error handling**: `try/catch` around async network calls; errors propagated to UI via status messages.
- **Naming**: camelCase for functions/variables, PascalCase for classes (`AudioPlayer`).
- **File organization**: each functional concern lives in its own module at the repo root.
